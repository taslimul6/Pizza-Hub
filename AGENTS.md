# PizzaHub project guide

Everything below is maintained by hand (the block above is generated by `next dev`).

## Stack

Next.js 16 (App Router, React 19, Cache Components, Turbopack) · Tailwind CSS v4 · shadcn/ui (**Base UI** flavor, not Radix) · Better Auth with MongoDB · sonner toasts · TypeScript.

Commands: `npm run dev`, `npm run build`, `npm run lint`, `npx tsc --noEmit`. There is no test runner, so check changes with `tsc`, `lint` and `build`.

## Conventions

- **Types go in `types/`**, grouped by area (`auth.ts`, `homepage.ts`, `navigation.ts`, `ui.ts`) and re-exported from `types/index.ts`. Import with `import type { Role } from "@/types"`. Do not declare `type` / `interface` inside component files.
- **One component per file**, beginner-friendly style: `useState` only, plain comments, sample data as a typed array at the top of the component.
- **Use shadcn/ui for every eligible element.** No raw `<button>`, `<input>`, `<label>`, checkbox or radio. Available in `components/ui/`: `avatar`, `badge`, `button`, `card`, `checkbox`, `dropdown-menu`, `input`, `label`, `radio-group`, `separator`, `sheet`, `sonner`, `tabs`. Add more with `npx shadcn@latest add <name>`, then review what it changed (see gotchas).
- **Links that look like buttons:** `<Link className={buttonVariants({ variant, size })}>`. Do not nest a `<Button>` in a `<Link>`.
- Base UI components use a `render` prop instead of Radix `asChild`, e.g. `<DropdownMenuItem render={<Link href="/x" />}>`. Checkbox uses `onCheckedChange`, radio group uses `onValueChange`.
- Toasts: `import { toast } from "sonner"`. The single `<Toaster />` is mounted in `app/layout.tsx`.
- `cn()` comes from the official shadcn `cn` package (`lib/utils.ts` re-exports it). It merges Tailwind classes like `tailwind-merge`.
- Use `getRoleHome(role)` and `isRole()` from `lib/roles.ts` instead of hard-coding role paths.
- Do not call `new Date()` in static components (Cache Components fails the prerender).

## Design tokens (`app/globals.css`)

Colors are defined once in `:root` using shadcn's semantic names filled with the PizzaHub palette, then exposed through `@theme inline`:

- `bg-primary` tomato red `#C8261B` (hover `bg-primary-600`, tint `bg-primary-100`), `bg-secondary` basil green, `bg-accent` cheese gold
- `bg-background` / `bg-light` cream `#FFF8EE`, `text-foreground` / `text-dark` espresso `#2A1A14`
- `text-muted-foreground` secondary text, `bg-muted` / `bg-sand-100` soft sand background
- `border-border`, `text-error`, focus ring `ring-ring` (blue)
- Fonts: `font-display` (Fraunces headings), `font-sans` (DM Sans). Shadows: `shadow-warm-md`, `shadow-warm-xl`.

Button variants (`components/ui/button.tsx`): `default` (red), `outline` (dark outline), `secondary` (green), `accent` (gold), `ghost`, `destructive`, `link`. Sizes: `default`, `xs`, `sm`, `lg`, `icon`, `icon-sm`, `icon-lg`. Badge variants add `accent`, `muted` and `dark`.

## Authentication

- `lib/auth.ts`: Better Auth, MongoDB adapter (database `pizzaPulse`), email + password, Google provider. Users have a `role` field: `customer` (default), `vendor` or `admin`. A create hook rejects any other value.
- `lib/auth-client.ts`: `authClient` (`useSession`, `signIn`, `signUp`, `signOut`) with `inferAdditionalFields` so `role` is typed.
- Environment variables are listed in `.env.example`: `BETTER_AUTH_SECRET`, `BETTER_AUTH_URL`, `MONGODB_URI`, `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`. Never commit `.env`.
- Google redirect URI to register: `<BETTER_AUTH_URL>/api/auth/callback/google`.
- After email sign in or sign up the forms redirect to `getRoleHome(role)`. Google returns to `/signin` and the proxy redirects by role.
- **Known gap:** the sign up form lets anyone choose `admin`. Restrict this (invite code or manual creation) before production.

### Route protection (`proxy.ts`)

Matcher: `/signin`, `/signup`, `/customer/*`, `/vendor/*`, `/admin/*`. The session is validated against the database (`auth.api.getSession`), not just the cookie.

| Visitor | Request | Result |
| --- | --- | --- |
| Guest | any dashboard route | redirect to `/signin` |
| Logged in | another role's area | redirect to their own area |
| Logged in | `/signin`, `/signup` | redirect to their own area |
| Right role | own area | allowed |

New dashboard sub-pages (e.g. `/vendor/menu`) are covered automatically by the prefix.

## Gotchas

- `npx shadcn@latest init` / `add` can rewrite `app/globals.css` and `app/layout.tsx` (fonts, base styles, `<html>` className). After running it, check `git diff` and restore the PizzaHub tokens and fonts.
- `bg-muted` is the soft sand background and `text-muted-foreground` is secondary text. The old `text-muted` class no longer exists.
- `experimental.agentFeedback` is `false` in `next.config.ts` because it triggered a dev-server reload loop.
- `.vscode/` is not part of the project work and is left uncommitted.
